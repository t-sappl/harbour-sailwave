# Sailwave – Design

This document describes the **architecture**, the **code and text conventions** and the **design decisions** of Sailwave: **what** is deliberately solved the way it is and **why** – including alternatives that were tried and **rejected**. It complements the code comments and is meant for anyone who wants to understand or contribute to the code. Open items are in [`TODO.md`](TODO.md).

---

## 1. Code conventions

- **Code and comments entirely in English** (the source code is published).
- **Log output:** only real problems, as `console.warn` (shows as `[W]`). No info logs.
- **Theme values instead of fixed pixels/colours.** Deliberate exceptions: opaque dark pill of the moon badge, white logo badges.
- **Prefer Silica components** (`PullDownMenu`, `RemorsePopup`/`remorseAction`, `ViewPlaceholder`, `TextSwitch`, `ComboBox`, `ValueButton`, `DetailItem`, `Separator`, `InfoLabel`).
- **Every delete action has a countdown** (remorse) – everywhere. **Important:** callbacks created inside a context menu run only after the countdown – by then the menu and its QML context are destroyed and names like `appWindow` or page ids are `undefined`. Therefore take all needed objects and values into **local variables beforehand** (otherwise: "Cannot read property … of undefined").
- **Messages:** only one banner type, `MessageBanner.qml`, via `appWindow.showMessage(text)`.
- **Never cache failed network results.**
- Expired entries in `search_cache` are deleted at start-up (`pruneSearchCache`).
- No test/development data in the code.

## 2. Texts

- Source texts in `qsTr` in **English**, consistently **sentence case** ("Track history", "Station history", "Search results").
- **American spelling** in the app and in the user-facing documents (README, STORE, PRIVACY): "favorite", "color", "license".
- **No colons** in labels ("Audio", "Sort") – like Silica components and Jolla apps.
- App name everywhere **"Sailwave"** (not "Sailwave Radio"). `harbour-sailwave-radio.desktop`: `Name=Sailwave`.
- No unclear abbreviations: "Popular" (instead of "Prio"), "128+ kbps" (instead of ">=128").
- Numbers with plural forms: `%n` or `%Ln` (locale format, e.g. "1,234 votes").
- Translations: German, French, Spanish; terms:
  - Track history = Titelverlauf / Historique des morceaux / Historial de canciones
  - Station history = Senderverlauf / Historique des stations / Historial de emisoras
  - Sleep timer = Sleep-Timer / Minuteur de sommeil / Temporizador de apagado
  - Home country = Heimatland / Pays de résidence / País de residencia
  - No direct address of the user in translations (no "Sie"/"du").
  - Playlist (M3U format) = Playlist / Liste de lecture / Playlist

## 4. Navigation

- **Ring navigation:** Top stations → Track history → Advanced search → Top stations, **both directions** by swiping. Implemented with `pushAttached` and rebuilding the stack (`[left neighbour][current page](right neighbour)`). **No `SlideshowView`.**
- The three ring pages are fixed instances (`ringMember: true`) so that state/scroll position are kept. No `initialPage` (Silica warns about an object instance); the start page is pushed in `Component.onCompleted` with `push(…, Immediate)`.
- Sub-pages (station info, settings, …) lie **on top of** the ring page; swiping back first unwinds that stack.
- **No copies of ring pages** from the pulley menu or the PlayerBar (removed because they behave differently). Only exception: "Open track history" (station info, PlayerBar) opens a **copy** of the track history page as a normal sub-page (`targetStationKey`: scrolls to the station and expands it; no ring swiping), so swiping back returns to where it came from.
- **"Similar stations" replace the station info page** (`openStationInfo(st, true)` → `pageStack.replace`), like the Maps app – no ever deeper stack.
- **Station info never twice** for the same station: `appWindow.openStationInfo()` – if it already shows this station nothing happens; if it is deeper in the stack, it jumps back there.
- Start page pulley menu: "Settings", "Manage favorites" (if there are favourites) and "Try again" on errors. "Station info" removed (duplicate – station info via the station name in the PlayerBar); instead a one-time hint above the PlayerBar ("Tap the station name for station info", `InteractionHintLabel`, flag `playerBarHintShown`; disappears on tap, after 8 s or when station info is opened).
- The glowing line at the top of pages with a pulley menu is the **Silica pulley menu indicator**, not a bug.
- **One-time hints, never two at the same time:**
  - **Swiping between the ring pages** (`RingHint.qml`): on the first start, 1 s after loading, only on the start page – Silica `TouchInteractionHint` (direction left, 3 runs) + `InteractionHintLabel` above the PlayerBar, text "Swipe sideways to switch between stations, track history and search". Takes no touches; ends after the last run or on any page change; flag `ringHintShown`. If the user has already swiped to another ring page, it is not shown at all. The PlayerBar hint waits while it runs.
  - **Empty favourites:** while there are no favourites, the start page shows a "Favorites" heading with "Tap the heart next to a station to add it to your favorites." in the list header (only once the lists have content, not in the search).
  - **First "Move" on the start page:** `InteractionHintLabel` "Groups, backup and more: pull down and choose "Manage favorites"" – the start page only offers sorting. Takes no touches (dragging near the bottom must keep working); 8 s or until the sort mode ends; flag `moveHintShown`.
  - **PlayerBar arrow:** right after the station name hint (1.5 s after it is gone): "Tap the arrow for recent tracks and the sleep timer" – the moon only exists in the expanded bar. Tap, 8 s, or expanding the bar ends it (expanding the bar earlier means it is never shown); flag `playerBarExpandHintShown`.
  - **Advanced search:** after the first search, "Search results appear at the bottom of the page" (above the PlayerBar) – with open filters the results can be off screen. Tap, 8 s or leaving the page ends it; flag `searchResultsHintShown`.
  - **Reset for testing:** press and hold the app icon on the about page → all hint flags reset (`AppSettings.resetHints()`).
- A ring indicator (3-part bar) was tried and removed.

## 5. PlayerBar

- **Only one, global PlayerBar** (in `harbour-sailwave.qml`). The lists/flickables of the pages with a PlayerBar (start page, track history, advanced search, station info) **end above the collapsed bar**: `anchors.bottomMargin: appWindow.playerBarBaseHeight` on the view itself. Only the part of the **expanded** bar that lies on top of the view (`appWindow.playerBarOverlap`, 0 while collapsed) is added as space in the **footer** (empty item), **not** as `ListView.bottomMargin`: Qt 5.6 ignores `bottomMargin` while the content is shorter than the view – the last rows were then hidden under the bar without being scrollable. The collapsed height is used on purpose: otherwise the list would shrink every time the bar is expanded.
- The bar takes all touches no element inside handles (its own `MouseArea` at the very bottom) – otherwise the page behind it scrolled when there was little content.
- Hidden on settings, about page, country picker, homepage dialog, favourites page, group name dialog, restore pages, sync conflict page and Sailfish pickers – by **name comparison** (`objectName`; pickers via `selectedContentProperties`), deliberately no "more robust" solution.
- **Cover field:** album cover fills the field, station logo as a light rounded badge bottom right. If the cover disappears, **the logo grows animated from the bottom right corner** (one shared animation value, logo is scaled, not reloaded).
- No alternating/cross-fading between logo and cover (rejected).
- **Sleep timer:** moon button **only in the expanded PlayerBar** (collapsed, the song title needs the space). Opens a row above the bar with 5, 10, 15, 30, 45, 60, 90 minutes and ✕ to stop. The last chosen duration is remembered. At the end playback is **paused**, not stopped; volume is restored. "Fade out" stays in the settings.
- Sleep timer is **not** in the pulley menu (was there, was moved).
- **Expanded: only "Track history":** titles of the current station, **3 visible, more scrollable within the area** (up to 30 loaded), below it fixed (does not scroll along) "Open track history" – quiet: small icon, same font size as the titles (was too dominant before). Shared component `TrackPreview.qml`, identical on the station info page. Station history removed from the PlayerBar (it is on the start page). The bar's height follows its content.
- **Background:** adaptive colour from the ambience (`adaptiveBarColor`): hue of the highlight colour, saturation ≤ 45 %, fixed lightness 17 % (dark) / 88 % (light), then contrast to highlight-coloured icons ≥ 3:1 (lightness shifted further if needed). Opaque, because the bar lies on top of scrolling lists. **Rejected:** fixed base tones #121212/#F0F0F0 + 35 % accent (calculated problem cases with very dark/pale/saturated accents); `Theme.highlightDimmerColor` (formula undocumented, not controllable); semi-transparent like the Jolla media player (list shines through). Limit: Silica does not provide the brightness of the wallpaper.

- **Context menus above the PlayerBar:** Silica keeps an opened menu inside the view's area. Since the views end above the collapsed bar (see above), Silica's own logic is enough – as in the Mail app, where nothing lies on top of the list. **Rejected:** a helper that scrolled the list while the menu opened: it fought Silica's own scrolling (moved too little) and moved the menu entries under the still pressed finger, so releasing triggered an entry ("Manage favorites" opened the favourites page). **Rejected:** a bigger footer below the lists (does not change Silica's scroll target; Silica menus never open upwards).
- **Leaving the favourite sort mode:** anchor is the favourite moved last if it is on screen (position at drop, corrected for scrolling since) – the view stays where it was dropped, e.g. at the bottom, and its group stays expanded; otherwise the topmost visible row; at the top → stays at the top.

## 5a. Landscape (1.1, prototype)

- **Player panel instead of the PlayerBar:** in landscape the height is short and a bar at the bottom would take a large part of it. The player becomes a column on the right (`PlayerPanel.qml`, 38 % of the width, always "expanded"): large cover with the logo badge, station (tap: station info) and song, large **previous / play / next** buttons (previous/next favourite, same rule as the cover and the lock screen – useful in the car), favourite heart, sleep timer, the latest titles with "Open track history". The pages end left of it (`anchors.rightMargin: appWindow.playerPanelWidth` on their views); the ring swiping stays on the left; the bottom margins (`playerBarBaseHeight`, `playerBarOverlap`, `playerBarHeight`) are 0 in landscape. On the pages that hide the PlayerBar (settings, favourites page, …) the panel slides out and the page gets the full width.
- **Window-level items turn with the pages:** Silica rotates each page, not the window. PlayerBar, panel, hints and message banner therefore lie in a layer (`uiLayer`) that copies the current page's size and rotation – otherwise they stay upright across the screen (same solution as Sailfeed). `allowedOrientations` and `_defaultPageOrientations` are both `Orientation.All` (`defaultAllowedOrientations` means portrait only on phones).
- The one-time PlayerBar hints (station name, arrow) are not shown in landscape – they point at the bar; they come later in portrait. The message banner is centred over the page area.
- **Rejected:** two ring pages side by side (conflicts with the ring navigation / `pushAttached`, like the `SlideshowView` before); keeping the bar at the bottom in landscape (too little height).
- Prototype: the panel duplicates logic of `PlayerBar.qml` (favourite state, sleep durations, track preview, cover); if it is kept, the shared parts move into a common component.

## 5b. Favorite tiles (1.1)

- **Large tiles of the favourites** (`FavoriteTilesPage.qml`): logo and name, about 3 tiles per row in portrait and 4 next to the player panel in landscape (tile size from the portrait width `Screen.width` as a fixed unit, so tablets get more columns). Groups as on the start page: a heading per group, favourites without a group last under "Other favorites". **Tap plays**, press and hold opens a menu with "Station info" (as everywhere in Silica). The playing station is highlighted; unreachable favourites are dimmed. Pulley: settings, manage favorites. Built the first time the page is shown (no logo downloads otherwise).
- **A fourth ring page left of the start page:** tiles → start page → track history → advanced search → tiles. The start page stays the start page; one swipe to the right shows the tiles. The ring is a list (`ringPages()`). The attached right-hand neighbour is remembered by the app (`PageStack.nextPage()` does not report an attached page that was not entered yet); if the ring changes, the stack is rebuilt around the current page instead of attaching over the existing neighbour – attaching the same page twice made Silica fail with "two consecutive entries of the same page instance" when turning the phone. With "only in landscape" the ring changes while the phone turns: then only the delayed ring-change handling rebuilds the stack (after the rotation, once the page stack is idle), never the regular ring check at the same time, and every rebuild (`_rebuildRing()`) checks that the stack was really emptied and never pushes a page that is already on top.
- **Setting "Favorite tiles":** Off (default) / Always / Only in landscape, plus the switch **"Open when turning to landscape"** (only while the tiles are not off). One choice plus a switch instead of three switches, which would allow contradicting combinations ("always" and "only in landscape"). With "only in landscape", turning back to portrait on the tiles goes to the start page. Opening on rotation only happens from a ring page – a station info or settings page stays where it is.
- Together with the player panel (5a) this is the car view: tiles on the left, player on the right.

## 6. Cover, MPRIS, album covers

- **Same image** everywhere (PlayerBar, app cover, lock screen): album cover with station logo badge bottom right, otherwise just the logo.
- App cover: moon badge with remaining time top left while the sleep timer runs.
- App cover without album cover: logo badge fixed at `Theme.iconSizeLarge` (not bound to `stationIcon.width` – that was a binding loop on `iconSize`).
- Cover actions: play/pause and "next favourite". The second action only appears if it would change the station (two `CoverActionList`s, one active). "Next favourite" stays **within the group** of the playing station; without a group, alone in its group or not a favourite: through all favourites (order as on the start page).
- **Next/previous favourite via MPRIS** (lock screen, Bluetooth headset, car): same candidates as the cover action, in both directions, wrapping around (`playFavoriteByStep`). Setting **"Stay within favorite group"** (`loopWithinFavGroup`, default on, as the cover always behaved): on = the playing station's group (without a group / alone in it / not a favourite: all favourites), off = all favourites. A station that is not a favourite: next starts the first, previous the last favourite. **Also while paused** – switching then starts the new station (in the car, "next" after a pause is expected to play). `canGoNext`/`canGoPrevious` follow the cover rule (`canPlayNextFavorite`), so the lock screen shows no buttons that do nothing.
- **MPRIS image** is created by the C++ helper `ArtComposer` (QML `grabToImage()` did not work in the background, Canvas crashed). Until the PNG matches, MPRIS gets the image URL directly (`cachedArtFresh` / `directArtUrl`).
- Errors of the C++ helper when loading logos do **not** mark logos as broken for the app (C++ may not read `.ico`, QML can).
- The lock screen only shows MPRIS images; there is no ring/cover display there.
- **iTunes search:** only for "Artist - Title", 1.5 s delay, rough artist matching, 600×600. Results in a session cache and permanently in the track history (`art_url`, `album_name`, `genre`, `itunes_artist`, `itunes_title`) – repeated songs do not query iTunes again. Can be switched off in the settings ("Song details from iTunes").
- **iTunes spelling of the current track** (`currentTrackDisplay`): PlayerBar, app cover and lock screen (MPRIS) show it as soon as there is a reliable match; the stream text remains the basis.

## 7. Station logos

- Sources (shared in `StationLogo.js`): 1. favicon from radio-browser, 2. Google favicon of the homepage (**corrected homepage takes precedence**). The Google fallback sends the homepage's domain to Google, so it can be turned off (setting "Load missing logos via Google", `googleLogoFallback`, default on) – then the letter avatar is shown; applies to `StationIcon` and the MPRIS image (`CoverArtCache.buildCandidates`).
- **Broken logo URLs:** a URL that fails to load is remembered app-wide (`appWindow.markIconUrlBroken`), so the next source is used everywhere. The set is a plain JS object – changing a key in it sends no change signal, so `markIconUrlBroken` also raises `brokenIconRevision`, which `isIconUrlBroken()` reads; otherwise the bindings in `StationIcon` never re-evaluated and a logo that had just failed kept its letter avatar in the lists, while places created later (PlayerBar, lock screen) already showed the Google fallback.
- Broken favicon URLs are remembered per session (`brokenIconUrls`), then a letter avatar.
- Letter avatar only when there is no logo (no URL or load error) – **not while loading**; the area stays empty until then. Otherwise the avatar flashes briefly, e.g. on the station info page (larger logo = separate image cache entry, loaded again).
- **Rejected:** small favicons on light tinted tiles, the plain logos looked better.
- **Rejected:** blur filter on all icons.

## 8. Pages in detail

**Start page (top stations)**
- Sections: favourites (possibly in groups), station history, top stations; or search results.
- **Every favourite belongs to exactly one group (or none) – deliberately 1:1.** Rejected: a favourite in several groups (mapping table, move vs. copy, "remove from group" vs. "delete", unclear cover action – too much complexity for users).
- **Favourite groups:** table `favorite_groups` (id, name, sort_order), `favorites.group_id` (NULL = no group). Without groups: one section "Favorites" as before. With groups: one collapsible section per group (state `favGroup_<id>`), favourites without a group last under "Other favorites" (same name on the favourites page); empty groups only on the favourites page (and as drop targets while sorting).
- **Sorting favourites on the start page:** context menu "Move" (long press is the context menu in Silica lists, so no "long press and drag"; no ready-made Silica component for reordering) → all favourites get a handle, heart/info buttons hidden, all groups expanded, empty groups visible as targets. Moving **across groups** like on the favourites page (consistent, otherwise not understandable for users). Dragging only at the handle (the list stays scrollable); while dragging the list scrolls by itself at the top edge or just above the PlayerBar. "Done" as a text action (no button – does not fit the page design) on the right between the search row and the first favourite group; it pushes the list down by its height on purpose (visible feedback for the mode). **Ending also by tapping** a header, a favourite row outside the handle or any other row (known from other apps). When starting and ending, the **topmost visible row stays in place** (or its group header if the group collapses again; if the page header is visible, the page stays at the top) – otherwise the list jumped because header and groups change. The list is never left locked (`interactive` is reset on every mode change). Order in column `sort_order` (migration: existing ones numbered alphabetically, new ones at the end); the cover action follows the order.
- **Favourites page (`FavoritesPage.qml`):** pure editing page (tap does not play, PlayerBar hidden). Groups: new (pulley, `GroupNameDialog.qml`), rename, move up/down, delete – **both**: "Delete group" (favourites → "Other favorites") and "Delete group and favorites", each with countdown. Favourites: handle on the right for dragging, also **between groups** (group = header above), the list scrolls along at the edge; only at the handle so the list stays scrollable otherwise; generous space below the list so the last handle is not at the screen edge (system gesture). Selection mode: mark favourites and groups, delete together (countdown); marked groups are deleted without their favourites unless those are marked too. Reachability + "Find alternative" as on the start page. Pulley: sync now (only with automatic sync), back up, restore, new group, select.
- **Reachability of favourites:** one request `stations/byuuid` for all (4 s after start, after adding, every 6 h; a failure keeps the old result). Broken favourites show "Not reachable at the moment" / "No longer listed at radio-browser.info" in the second line + context menu "Find alternative".
- **Station history includes favourites**: it shows the last 5 stations played, whether favourite or not; if empty, the section is missing. A station can therefore appear in a favourites group and in the station history at the same time (rows are told apart by section, `rowKey`).
- Collapsing/expanding without rebuild: only the rows of the affected section are removed from or inserted into the list model (`toggleSection`), animated via the ListView's `add`/`remove`/`displaced` transitions (only active while toggling). **Rejected:** collapsed rows with height 0 in the model – that broke the ListView's content height (no longer scrollable to the end). Collapsed sections therefore also load no logos. Loading more top stations only appends (not while collapsed).
- **Start page: no `clear()` on updates.** `rebuildMainList()` builds the wanted rows (`buildRows`, each with a unique `rowId` = `rowKey` + counter) and applies only the differences (`syncRows`: remove what is gone, move/insert the rest into place, `set()` changed values – delegates stay, logos are not reloaded). If rows changed, a visible row is kept exactly in place (`restoreAnchorTimer`; not while the list moves or another anchor is pending, e.g. sort mode): preferably the row of the **playing station** (`currentStationAnchor` – after tapping a station it stays under the finger and new rows above extend the list upwards), otherwise the topmost visible row (`captureAnchor`). Since the delegates survive the sync, the anchor's delegate is put back at its old screen position (`forceLayout()`, then `contentY`); only if it is gone the row is searched by key. Only switching into/out of the search still clears. **Rejected:** `clear()` + rebuild – playing a station made the page jump twice (station history, then top re-scoring 0.5 s later).
- **Start page: order frozen while on screen.** `orderFrozen` = page not `Inactive` and app in the foreground. Then the station history keeps its order (new stations at the top of the section, removed ones disappear) and the top stations are not re-scored (`topResortPending`); the new order is applied as soon as the page is off screen or the app in the background. **A played top station stays in the top stations** – it is listed in the station history too until the page is off screen; only favourites are removed from the top stations right away (`pruneTopStations`). **Rejected:** removing it from the top stations immediately – the tapped row vanished under the finger and reappeared further up, which looked like a jump. Same principle as the track history. **Rejected:** re-ordering immediately (the tapped row moved away under the finger).
- Error state with "Try again" below the list and in the pulley menu.
- **Loading top stations:** triggers (favourites, station history, current station, home country) are bundled by a 500 ms timer. The loaded stations (up to ~900) stay in memory as a **station pool** and are only re-scored locally on changes. Network only if the pool is older than 10 min, the requests change (top country/language/tag of the profile) or on "Try again". Big busy indicator only while nothing is shown yet.
- **Snapshot** of the first 100 top stations in `app_state` (`top_stations`), up to 24 h old, shown immediately at start-up; written only after a real network load. "Clear cache" deletes it as well.

**Track history**
- Station logo in the header row **small** (`iconSizeSmall`) so blurry favicons do not stand out; structure via indentation.
- Track rows: cover in the same small size; **without a cover the area stays empty** (no icon), titles stay aligned.
- **Two lines** instead of truncation: song title on top (max. 2 lines), below "Artist · Genre · Time" (`TrackText.js`, also on station info and PlayerBar). No marquee.
- **Multi-line titles:** some stations send titles with line breaks. **The track history keeps the break** (shown on up to two lines): `TrackText.clean` only tidies up (`\r\n`/`\r` → `\n`, spaces/tabs inside a line → one space, empty lines dropped) – at the source (`rawTrackTitle`) and when shown. Places with room for one line use `TrackText.oneLine`: PlayerBar, app cover and lock screen/MPRIS (`currentTrackDisplay`), the previews (`TrackPreview`), the iTunes search (`parseTitle`) and the artist in the details line. **Rejected:** turning every break into a space everywhere.
- The title label's height is set **explicitly** from `lineCount` × line height (`FontMetrics`, max. 2 lines): in Qt 5.6 a wrapped + elided `Text` does not reliably update its `implicitHeight` when the text changes later (iTunes title via `setProperty`) – a two-line title overlapped the row below.
- **iTunes spelling:** `artistName`/`trackName` are only stored (columns `itunes_artist`, `itunes_title`) if artist AND title match the stream text ignoring case, punctuation and bracket additions – iTunes only corrects the spelling; otherwise the stream text stays. `previewUrl`/`trackViewUrl` deliberately not used (browser = media break, no iTunes app on Sailfish).
- **Search:** search field at the top of the list (title, artist, genre, station); matching stations expanded, collapsing only applies to this search; also no rebuild on playing while a search is active. ListView with `currentIndex: -1` (otherwise the search field loses focus with every letter – same fix as in the advanced search) plus a safety net: focus is given back after a rebuild.
- List thumbnails in 200×200 (iTunes URL rewritten), stored stays 600×600.
- Rebuild only while the page is visible; otherwise only marked as outdated (same principle in the PlayerBar preview: only expanded and app in the foreground). The PlayerBar marquee pauses in the background.
- Pulley menu hidden when the history is empty.
- **`SilicaListView`**, not `Column` + `Repeater` (the Repeater created all ~200 rows at once: 466–507 ms at start-up and when swiping, measured with the QML profiler). Collapsing as on the start page: collapsed stations have no rows in the model, `toggleStation` inserts/removes (transitions only meanwhile). Covers load only for visible rows.
- **Deleting an entry** removes only that row (and the station header if it was the last entry) – no rebuild, the scroll position stays. The page's own `trackHistoryUpdated()` is ignored there (`_ownUpdate`); other places (PlayerBar, station info, ring instance) update.
- **Jump from station info / PlayerBar** ("Open track history"): scrolls via `positionViewAtIndex` while the page slides in and **once more when it is fully shown** – while sliding in, the rows are only being laid out (two-line titles get their height late), so the first position could cut the station header in half. The header is placed with **`Theme.paddingLarge` space above it** (the name was still cut off at the edge) – the same for the first group. **Rejected:** going to the very top including the search field for the first group – it jerked.
- **No rebuild while the page is visible:** `applyHistoryChanges` compares the stored with the shown history (station name + timestamp) and changes only affected rows – new title at the top of its group, new station as a group at the very top (expanded), cover via `setProperty`, dropped entries removed. The order of the groups stays; it is re-sorted the next time the page is opened. Reason: the list jumped to the top while new titles arrived. **Exception: tapping a track** moves that station's group to the very top, expands it and scrolls to the top (`moveStationToTop`) – the station that was just started is what the user wants to see; only new titles arriving by themselves keep the order.

**Station info**
- Header: logo, below it **Play centred, favourite heart on the right** (invisible placeholder on the left).
- **Quick search requests:** name and tag search for the longest word (as before) **plus, with several words, the whole phrase as part of the name** (`search?name=<phrase>`). Reason: for "radio kä" the longest word "radio" only brought the 100 most popular "radio" stations, none containing "kä" – "Radio Kärnten" appeared only once "kärnten" was typed completely, which looks illogical. radio-browser matches the name search anywhere in the name, so the phrase finds it while typing. Other word order ("kärnten radio") still works via the longest word. The advanced search already sends the whole text.
- **Quick search order (start page):** names **starting with** the search phrase first, then names **containing** it as a whole, then all other matches (every word may match anywhere in name, tags, country, language – "si" also matches "blasmusik"); A-Z within each group, at most 50. Before: A-Z only, so "Radio si" did not show Radio SI at the top. The cache key ignores the word order, so the cache holds the unranked matches and they are ranked for the phrase as typed. **Advanced search too:** with a typed text the same grouping comes first, within each group the chosen sorting (popular with home-country weighting / A-Z); with filters only, unchanged. Shared code: `RadioApi.groupByNameMatch(list, phrase)` – groups while keeping the order within each group, so each page sorts first and then groups (also independent of whether the JS sort is stable).
- **Country names:** the lists (`StationDelegate`, favourites page) and the station info show the country by its **code** from `CountryData` (`displayName`): short ("United Kingdom" instead of radio-browser's "The United Kingdom Of Great Britain And Northern Ireland") and German in a German UI; French/Spanish use the English name (CountryData has no other names). Without a known code the stored name is shown. The station history therefore also stores the country code (new column, added by migration; older entries keep the stored name). Searching still uses radio-browser's English names. In the station info a state equal to the country (radio-browser entries like "Spain · Spain") is left out.
- **Station names tidied up:** some names at radio-browser start with spaces/tabs or contain line breaks. In the one-line rows that shifted the name to the right, made the row overflow into the next one, and A-Z sorting put such names first. `RadioApi.cleanName` (all whitespace runs → one space, trimmed) is applied in `stationFromApi` (all API data), in `playStation`/`restoreLastStation` (PlayerBar, cover, lock screen, histories), when favourites are loaded, in `currentVal("name")` of the station info, and when shown in `StationDelegate` and the track history headers (data stored by older versions). Stored keys (stream URL, the track history's station name) are not changed.
- **Same stream listed twice at radio-browser:** some stations have two entries with the same stream URL but their own name, tags and votes (e.g. "Radio Si" with adult contemporary/international/public radio/rtvslo and "Radio Si - Radio Slovenija International" with local news/traffic/world music/world news). The app identifies a station by its stream URL (favourites, history, "now playing"), so `RadioApi.fetchAll` keeps one per URL – search, top stations and similar stations alike. **Which one:** more tags (up to 5 count) + log10 of the popularity (votes × 5 + clicks); equal → the entry changed most recently (`lastchangetime`); still equal → smaller uuid as a fixed, arbitrary rule. **Rejected:** "larger uuid = newer" – radio-browser uuids are partly v1 (time-based, but not ordered as text) and partly v4 (random). Before, the answer that arrived last won (random). **Rejected:** showing both – two rows with one shared heart and history. A favourite keeps its own uuid (station info loads that entry), so its station info can show other tags than the search result.
- **Similar stations:**
  - **Tags:** tags naming only the station's **own** country or language (e.g. "slovenia", "english") are ignored – country and language are scored from their own fields. Other countries/languages stay ("greek" on a station in Germany describes its programme; a global country/language filter would also hit genres like "latin").
  - **Type tags** (`RadioApi.isTypeTag`: public radio, international, community/college radio, news, local news, talk, traffic, regional, local, …) describe the kind of station, not its programme: never searched worldwide and only counted as shared tag **within the same country**. Reason: Radio SI (Slovenia; adult contemporary, international, public radio, rtvslo) got Houston Public Media and Calgary AC stations – "public radio"/"adult contemporary" are dominated by North America worldwide, and "rtvslo" (4th tag) was never searched.
  - **Requests:** the first 3 **genre** tags (non-type) worldwide, in the station's language and in the home country (if different); **all** tags (up to 6, incl. type and brand tags like "rtvslo") in the station's own country – this finds sister stations. `tagExact`, by popularity, 40 each.
  - **Points:** shared tag 3, same country 4, same language 4 (**2 if the station has several languages** – a shared world language says less), home country 2, **neighbouring country 2** (`CountryData` borders), popularity `log10(clicks+1) × 0.3`. Reason: the server root is no WebDAV folder (PROPFIND there fails), which showed up as "check the URL" with a Hetzner Storage Share.
- **WebDAV:** the same file in `<URL>/Sailwave/`. ETag remembered after every sync; before uploading a HEAD request – different ETag (or first sync with an existing file) = conflict → `SyncConflictPage`: "Merge both" (recommended) or "Keep this device's". Failed upload → `webdavPending`, retried at the next change, at start-up or with "Sync now". Requests in C++ because QML XHR in Qt 5.6 does not reliably support all WebDAV methods. **Password in Sailfish Secrets** (see below).
- **WebDAV password (Sailfish Secrets):** C++ `SecretStore` (`secretStore`), one app collection `sailwave` in the default encrypted storage plugin, owner-only, locked with the device and kept unlocked after the first unlock (`DeviceLockKeepUnlocked` – no own password prompt). Operations are queued (a running store cannot be overtaken); storing deletes an existing secret first. **Storing is tried up to three times:** as is, after creating the collection, and once more after 1.5 s – on the very first save the attempt right after the access question could fail although access was granted (the password was only kept when entered a second time); intermediate failures are logged as `[SecretStore]` warnings, only the last one is reported. **The collection is only created when storing fails** (in practice once, at the first save): creating a collection makes the system ask the user "Allow access" – **rejected:** creating it at every start ("already exists" ignored), which brought that question at every start. **The password is only read when needed:** right after the start only with automatic sync; otherwise on the first server access (`FavoritesBackup.dav` → `ensurePasswordLoaded()`) or when the WebDAV settings are shown. In QML the password is only held in memory (`AppSettings.webdavPassword`, changed via `setWebdavPassword()`, saved 0.8 s after the last letter); the settings table only keeps the flag `webdavPasswordStored`. The API is asynchronous: `webdavPasswordReady` – WebDAV requests wait for it (`FavoritesBackup.dav`). **Migration:** a password from the settings table of older versions is moved to Secrets at start-up; the database row is deleted only after that worked. **No fallback to the database** if Secrets fails – the password then only works until the app is closed, the settings show a hint (`webdavPasswordError`); otherwise the security gain would be gone. Sailjail permission `Secrets` (allowed in the Jolla Store since Jolla added Secrets/Crypto to the allowed APIs).
- Sailjail: needs `Documents` (writing) and `Downloads` (file picker: backups received e.g. by mail).

## 9. Network and data

- **Home country:** settings > IP (ipapi.co with user agent, fallback api.country.is) > system language; 6 s time limit.
- **API URLs** always via `RadioApi.apiUrl(path)` with the neutral host `server.api.radio-browser.info`; the real server is inserted per attempt, the URL (and thus cache keys) stays stable.
- **radio-browser:** server list from `all.api.radio-browser.info`, failover only for radio-browser URLs on 0/403/429/5xx; rotates only if the failed server is still the active one.
- **Qt 5.6 workaround** (`networkaccess.h`): network managers stay "accessible", otherwise the app hangs after flight mode.
- **Disk cache for images** (`networkaccess.h`, `QNetworkDiskCache`): the network manager of the QML image loader (own thread) gets a cache in `~/.cache/…/images/qml` (40 MB), `ArtComposer` its own in `images/composer` (20 MB) – never two caches in the same directory. GET requests with `PreferCache`: cached images come from the cache without asking the server (also after a restart and offline); logos/covers practically never change. The main thread's manager (XMLHttpRequest: radio-browser, iTunes search) gets **no** cache – API answers have their own 10-minute cache.
- **"Clear cache"** in the settings clears the search cache, the top station snapshot **and** both image caches (`imageCache.clear()`, context property from C++; `clear()` runs in each cache's thread). Images already shown stay in memory until a restart.
- **Privacy policy:** `PRIVACY.md` (English only, linked on the about page). It must list every online service the app contacts: radio-browser.info (clicks, votes), the stations' stream and logo servers, the Google favicon fallback, iTunes (song titles to Apple), ipapi.co + api.country.is (country by IP), the WebDAV server (if configured). The README privacy section is a short version of it – keep both in line when data flows change. **In the app as well:** the about page ("Data sources") names every optional service with how to avoid it – Google favicons and iTunes "can be turned off in the settings", the country detection via ipapi.co / api.country.is "only while set to automatic"; the home country setting itself says that "Automatic" detects the country from the IP address via ipapi.co.

- **Database tables on first access:** `PersistentState` and `FavoritesStore` (same SQLite database) create and migrate their tables in `db()` on the first access, not only in `Component.onCompleted` – the order of `onCompleted` handlers is not defined, and on a fresh install the start page read `station_history` before it existed.

## 10a. Sailjail (sandbox)

## 10c. Large system font (since 1.1.1)

- **Heights follow the text.** No row, heading or bar has a fixed height any more that a large system font could overflow: height = `Math.max(old fixed size, text height + padding)`. At the default font size the result is the old fixed size, so nothing changes there. Affected: `StationDelegate`, favourites page (rows, group headings), `TrackPreview` (`rowHeight`, measured with `FontMetrics` of the two label fonts), section headings on the start and track history pages, "Done" row, `PlayerBar.collapsedHeight` (all pages use it as bottom margin through `playerBarBaseHeight`), favorite tiles (one `tileHeight` for all tiles, so the rows stay even).
- **Advanced search filter rows** (`FilterSection`): a selection that does not fit starts at the left and fades out at the end (right-aligned it lost the first entries); short values stay right-aligned.
- **Rule for new lists:** never `height: Theme.itemSizeX` around labels; use `Math.max(Theme.itemSizeX, textColumn.height + 2 * Theme.paddingMedium)`. Test with Settings > Display > Font size = Huge (TEST-PROTOCOL 34).
- **English plural forms:** `translations/harbour-sailwave-radio-en.ts` holds only the numerus messages ("%n favorite" / "%n favorites"); all other English texts come from the source.

## 10e. Pausing other players (v119)

Sailfish has no audio focus: a second app that starts playing does not pause the first. `MprisOthers.qml` (loaded through a Loader like `MprisIntegration.qml`) pauses every other MPRIS player that reports "Playing" at the moment `isPlaying` becomes true, so it covers every start route (app, cover, lock screen, headset). One `MprisManager` per foreign service (`singleService`), so each status is current and can be read at once. Only the change to "playing" triggers it, so there is no loop. Own name `org.mpris.MediaPlayer2.harbour-sailwave` is excluded. Sailjail: the Audio permission has `dbus-user.own org.mpris.MediaPlayer2.*`, which for the D-Bus proxy normally includes talking to those names; to be confirmed on the device (TEST-PROTOCOL 36). The headset key (PlayPause) goes to the player Sailfish picks, possibly the paused Sailwave although another player is playing: in that case `onPlayPauseRequested` pauses the other player instead of starting Sailwave. Only PlayPause is treated this way; an explicit Play (lock screen button of Sailwave) still starts Sailwave.

## v128g/h – Station logos: tile that works on every ambience

- Problem: Radio Aktual (dark lettering, transparent) unreadable; the faint plate (alpha 0.15, v128) was invisible on dark, useless on light or red ambience, and a transparent logo on an album cover depends on the cover. (1.1.1 had no plate at all and a white badge on the cover.) Decision (11-13): tiles with their own contrast, independent of the ambience and the cover.
- `StationIcon` (v128h): the shown logo is rendered into a texture (`ShaderEffectSource`, `hideSource`) and drawn by one fragment shader: edges transparent (middle of the top/bottom edge, alpha < 0.6) → tile, logo at 76 %; otherwise no tile, logo fills the box. Tile colour: average brightness of the opaque pixels (unpremultiplied, alpha > 0.5) > 0.8 → dark tile `#2b2b2b`, else light `#f2f2f2` (dark and coloured logos, e.g. ORF red, go to the light tile). Hairline rim on tiles so they do not melt into a similar background. The whole icon is clipped with rounded corners (layer + mask shader, corner 0.2). `shadow` (badge on a cover): soft shadow below.
- `composeOnGpu` (default true): switch back to the plain logo with a margin if the texture route does not work on a device.
- PlayerBar / PlayerPanel: the badge rectangle is transparent, `shadow: artBox.hasAlbum`; the white badge is gone, the tile comes from `StationIcon`.
- `ArtComposer` (lock screen / MPRIS image): same rule in C++ (`drawLogoTile`): tile if the logo is wide or its top/bottom edge pixel has alpha < 0.6; brightness over pixels with alpha > 128; shadow; opaque logos clipped with rounded corners. Without a cover the logo sits on a tile at 80 % of the image.
- Known limit: multi-coloured logos (black lettering with white areas) can lose parts on the wrong tile; the clean fix (trim, check, render once in C++ for lists, cover and lock screen) is postponed until after 1.2. Not verified on a device: thresholds (0.6, 0.8, 76 %) may need adjusting.
